# Инструкции проекта

Перед работой прочитай README и актуальные документы проекта, если они существуют.
## Синхронизация между компьютерами — решение владельца от 27 октября 2026

- Владелец разрешил обычные commit и push результатов порученной работы в существующий origin без повторного подтверждения. Это правило действует на Windows и Mac при работе Codex в проекте; оно не запускает фоновую синхронизацию. Явная просьба не коммитить или не отправлять имеет приоритет.
- Перед изменениями определить настоящий Git-корень, текущую ветку, origin и upstream; проверить `git status`, staged-изменения и локальные неопубликованные коммиты. Выполнить `git fetch origin` и сравнить HEAD с upstream. Для обычной main использовать origin/main; не переключать чужую рабочую ветку автоматически и не объединять её с main ради синхронизации.
- Если рабочее дерево и индекс чистые и возможно fast-forward, выполнить `git pull --ff-only` для текущей отслеживаемой ветки. Если ветка уже актуальна, повторное скачивание не нужно. После обновления перечитать изменившиеся инструкции и документы.
- При местных изменениях сохранить их: не делать автоматические stash, reset --hard, clean, checkout/restore поверх файлов. Если удалённых обновлений нет, можно работать, отделяя изменения задачи от уже существовавших. Если обновление затрагивает незавершённую работу, история разошлась, нет понятного upstream или доступа к сети, сообщить конкретную причину и согласовать только необходимое действие; не выдавать репозиторий за синхронизированный. Независимую безопасную работу можно продолжить с явным указанием ограничения.
- После содержательной работы обновить соответствующую документацию, проверить результат и diff. Добавлять в индекс только файлы или фрагменты текущей задачи, затем сделать осмысленный коммит и обычный push в соответствующую ветку origin. Не использовать общий `git add .`, когда есть посторонние изменения. Уже подготовленные чужие изменения и неизвестные локальные коммиты не включать и не отправлять автоматически: push публикует всю неопубликованную историю ветки.
- Не создавать пустые коммиты. Для задачи без изменений файлов коммит не нужен. Не отправлять секреты, локальные конфиги и игнорируемые файлы; не менять приватность репозитория. Вложенные самостоятельные репозитории синхронизировать отдельно, не добавлять их в родительский Git.
- При отклонённом push сначала выполнить fetch и проверить новые коммиты. Не применять force push и не переписывать опубликованную историю. Если объединение затрагивает чужую работу или требует выбора смысла, остановить отправку и сообщить, что нужно решить; локальный коммит сохранить.
- В конце проверить результат push и состояние ветки. Кратко сообщить коммит и факт отправки; при ошибке явно указать, что осталось только локально и какой следующий шаг нужен. Правило переносит только отслеживаемые файлы Git, не чаты, панель приложения или отсутствующие исходники.
